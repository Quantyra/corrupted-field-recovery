## 2. Ranked findings

Labels: **[Demonstrated]** means I showed it by derivation or code trace. **[Clarification]** means the text is correct or plausible but under-specified. **[Formal gap]** means a missing bridge for certification. **[Suspicion]** means unverified. **[Observation]** means no fault.

### F1. Medium. [Clarification] The cost claim has no machine model
**Location:** Theorem 1, eq. (cost); §6 "Complete resource accounting".

"Bit-time" and "working space" are claimed without naming a model. It could be a bit-cost RAM with O(log)-cost addressing, a multitape TM, or a Boolean circuit count.

The bound is model-dependent. Under a bit-RAM, my stage counts agree with §6:
- O(n⁶) for the balance solve
- O(n⁴) for the defect image
- O(n⁷) for the compatible columns
- O(n⁶) for exterior columns with mutable arrays, or O(n⁹) for Python's packed integers
- O(n⁹) for the coefficient elimination

Per trial this is O(n⁹) time and O(n⁶) bits, so the n¹²/n⁸ envelope holds with margin.

Under a single-tape TM, a naive simulation of random access into an O(n⁶)-bit elimination workspace costs Θ(n⁶) per access. That gives roughly n¹⁵ for the O(n⁹) elimination, which exceeds the envelope. A careful sweep-based layout can probably stay inside the bound, but that is an unproved implementation obligation.

The released text therefore does not fix a target that M6 can certify. Plan M0 chooses a model, but the manuscript has to adopt it in a recorded correction. Otherwise "certifying the released theorem" is ill-posed.

### F2. Medium. [Clarification] The soft-O convention weakens the space claim and is unnecessary for time
**Location:** Theorem 1, the sentence "the soft notation hides logarithmic factors in n and h+1".

Read multiplicatively, Õ(n⁸ + log(h+1)) means O((n⁸ + log(h+1))·polylog(n, h+1)). That allows n⁸·logᵏ(h+1) workspace, which grows with h. This contradicts §6's intent that "storage has no factor N" and that only the counter depends on h.

- **Space fix:** state the bound additively, for example O(n⁸ + log(h+1)), or the tighter O(n⁶ log n + log(h+1)).
- **Time fix:** binary-counter increments and decrements are amortized O(1), so total counter work is O(N + log N), not O(N(R + log(h+1))). This allows a plain O(2^{4R}·h·n¹²) with no tilde. That statement is stronger and much easier to formalize than a multi-parameter soft-O.

### F3. Low–Medium. [Clarification] The resource justification mixes in Python interpreter overheads
**Location:** §6, "Polynomial index and interpreter representation overheads are absorbed conservatively…"

The theorem is about the algorithm of §5, not about `src/recovery.py`. Including interpreter overhead in its justification blurs the separation the paper wants to keep between the theorem and the implementation. The O(n⁹) packed-integer exterior bound is a property of the Python code, so it belongs in a remark.

The mathematical cost argument should rest only on the abstract model from F1. The plan already forbids "interpreter overhead" as a cost hypothesis. The manuscript text should match that.

### F4. Low–Medium. [Formal gap] Symmetry facts that justify computing only i < j are unstated
**Locations:**
- `recovery.py:common_balance` emits equations only for i < j.
- `recovery.py:imbalance_image` uses only pairs i < j, with the comment "Diagonal pairs vanish".
- §3 says W(D_T C) is "obtained by binary elimination on explicit coefficient slices".

Both shortcuts are correct, but each depends on a fact that appears neither in the manuscript nor in the plan:
- (a) Each B_j is symmetric, so the diagonal balance equations B(Te_i, e_i) = B(e_i, Te_i) hold automatically.
- (b) D_T C is symmetric in its first two arguments, because D_T C(y,x,·) = C(Ty,x,·) + C(y,Tx,·) = D_T C(x,y,·) by symmetry of C. Also D_T C(x,x,·) = 0.

Together these show that the span over i < j equals the full third-mode image. D_T C is not alternating in all three arguments, but it is symmetric and has zero diagonal in arguments 1–2. That property is exactly what the computation uses. Plan M2.6 ("connect exact coefficient slices") should list (a) and (b) as named lemmas.

### F5. Low. [Clarification] "First coordinate of v₄" is ambiguous
**Location:** §4, "the first coordinate of v₄ has fibers of size at most q²".

The argument only works with coordinates **relative to the sampled basis (v₁, v₂, v₃)**. In that basis, v₄ ↦ a is a K-linear surjection with fibres of size q², and this matches Lemma 4's a. The preceding sentence talks about "field coordinates", which suggests f-coordinates instead. With that reading the generator condition would not be the one Lemma 4 needs.

The proof is correct under the intended reading, but the wording should be fixed because M3.3 will formalize it.

### F6. Low. [Demonstrated, out of promise, harmless] Python rejects the irreducible polynomial p = X
**Location:** `recovery.py:irreducible`, the guard `modulus < 3`. This is reached through `Field.__init__` and `verify`.

Modulus 2 encodes p = X, which is irreducible of degree 1. The manuscript's test (X^{2^s} = X, with no gcd conditions for s = 1) accepts it. Python rejects it.

- `verify` therefore returns False on a valid s = 1 certificate with p = X.
- `recover` never emits one: T = 0 gives tail 0 and is rejected, while T = I gives p = X+1, which is accepted.

Soundness is unaffected, and s = 1 lies far outside s ≥ 2R+5. The Lean verifier specification should still choose deliberately: either follow the manuscript and accept p = X, or add the explicit restriction s ≥ 2.

### F7. Low. [Demonstrated, unreachable] `verify` is not literally total
**Location:** `recovery.py:verify`, the `except` tuple, and `Field.trace`.

`Field.trace` can raise `ArithmeticError`. Only its subclass `OverflowError` is caught. The raise is unreachable because `Field.__init__` checks irreducibility first, so the trace always lies in F₂. `MemoryError` and `RecursionError` are not caught either.

This is irrelevant to the mathematics. It does mean the docstring's "total" depends on an invariant, which is a point a future refinement project would have to prove.

### F8. Low. [Formal gap / labelling] `coverage.json` marks `two_translate_image` as "proved", but the export is a generalization that has not been connected to the manuscript
**Location:** `formal/coverage.json`, obligation `two_translate_image`. The export is `Independent.lean:two_translate_of_disjoint`.

The Lean statement differs from the manuscript lemma in four ways:
- It is over a generic field and uses subtraction.
- It assumes a globally invertible T rather than injectivity of T* on U.
- U is the range of `u.dualMap` for an abstract surjection u.
- It does not connect `modeImage` to W(E) on F₂ⁿ.

I checked the Lean proofs by reading them and they are mathematically correct. The `isolate` step in `two_translate_modeImage` does not even need alternation, and `joint_surjective_of_disjoint_duals` is a correct dual-annihilator argument. The plan's prose acknowledges all of this, but the machine-readable status does not.

Suggestion: use statuses such as `proved_generalization` / `bridged`. Then a reader of the JSON alone does not count the manuscript lemma as covered.

### F9. Observation. Clean quadruples always contain the scalars in their balance space
For any clean quadruple, whether or not it is a basis or contains a generator, the contractions of C equal those of C₀. Multiplication by any t ∈ K balances every C₀-contraction by K-multilinearity. So K ⊆ balance space always holds, and the check `len(balances) == s` alone already implies balance space = K.

This has three consequences:
- Lemma 4 splits into a trivial inclusion (K ⊆ balance space) and the real one (balance space ⊆ K, given a generator).
- It explains why the test's assertion "dim = s ⇒ scalar space" holds on every clean draw, including the s = 5 loop that has no generator filtering.
- It slightly simplifies M2.

### F10. Observation. Probability constants are loose but correct
γ ≥ 1 − 1/4 − 1/32 > 23/32, which is much stronger than the stated "γ ≥ 1/4". The union bound charges 2^{2r} − 1 pairs where only the 2^r(2^r − 1) pairs with u₁ ≠ 0 can contribute roots. The per-trial bound 2^{−4R−3} is valid either way. For formalization this slack helps: prove the cleanest sufficient inequality.

### F11. Observation and challenge. The conclusion is deliberately weak
The theorem guarantees *some* compatible representation, not the planted one. That is stated honestly. It raises an open question the paper neither claims nor addresses: is the representation unique up to field isomorphism and GL₃(K) when s ≥ 2R+5?

Two representations differ by Tr(c det) − Tr(c′ det′), which would have to be supported on ≤ 2R covectors. That looks rigid, but I have **not** proved it. Readers should not interpret "recovery" as identification of the planted structure. The cubic bound s ≥ 2R+5 does not transfer to the phase-recovery application, which keeps its own s ≥ 7R+5 condition. The manuscript states this correctly.

### F12. Observation. Executable evidence for in-promise nonzero corruption is fixture-assisted only
**Location:** `check_recovery.py:main`. The cases s = 7 and s = 11 use `good_tape`, which filters the vectors against the planted support and scans scalars. The only ordinary seeded run inside the promise is s = 5 with R = 0, which has zero error. The manuscript discloses this correctly.

In `good_tape`, the comparison `span(...).keys() ==` compares pivot positions, not subspaces. It is still correct when combined with the following containment check.

## 3. Recommended changes to the Lean completion plan

1. **M0: put the cost model and O-convention into the manuscript, not only the plan.**
   - Treat F1 and F2 as statement-changing findings with a recorded correction (for example, v0.1.1 errata). Without this, M6 has no fixed target in the released text.
   - Prefer the additive space bound and a tilde-free time bound using amortized counter increments.

2. **M0: freeze a reviewed `Spec.lean`.**
   - Put `def MainStatement : Prop` (input encoding, promise, `Represents`, and the constructor's type) in a small file that humans review and that is hash-pinned. The final declaration is `theorem main : MainStatement`.
   - Build an audit that generates `coverage.json` from Lean. A metaprogram should emit declaration names, a hash of each elaborated type, and the transitive axioms. Fail if the type of `main` differs from `MainStatement` or if the hash of `Spec.lean` changes.

3. **Add non-vacuity checks to M1.**
   - Prove in Lean that the promise is satisfiable for a concrete instance. Small s is enough for satisfiability; s = 5 with R = 0 lies inside the promise.
   - Prove that the verifier accepts one concrete valid certificate and rejects one tampered certificate, using kernel-checked computation.
   - This catches encoding bugs that would make the main theorem vacuously true. Keep the instances small so kernel reduction stays tractable, and record their axiom output.

4. **Reorder so verifier soundness is the first standalone deliverable.**
   - "Accept ⇒ all-vector representation" needs only part of M1, the soundness direction of the Rabin test, and the fact that wedge forms are alternating.
   - It does not need M2, M3, the exterior-basis *spanning* result, or Rabin completeness, which matter only for good-trial completeness.
   - This produces an early, fully certified "every output is correct" result.

5. **M5: replace adaptive-stopping coupling with a stateless decomposition.** Trials carry no state that affects control flow; the rejection counters do not.
   - Prove `recover tape = firstSome (i ↦ trial(block_i tape))`.
   - Failure is then exactly the product event ∏ᵢ {block i fails} on the Fintype `Fin N → Block`.
   - Pr[fail] = (1 − p)^N follows by counting cardinalities.
   - Early stopping matters only for consumed bits and cost (M6).
   - Model the tape as `Fin N → (Fin 4 → BitVec n) × BitVec s`, and prove its equivalence to a flat bit stream once.

6. **M3: make unconditional counting primary.**
   - Prove #{good 5-tuples} ≥ 2^{4n+s−4R−3} by a Fubini-style sum over A⁴. For each fixed good quadruple, the map from scalar index to t is a bijection Fin 2^s ≃ K, so at most τ(s) + 2^{2r} − 1 indices are bad.
   - Keep β and γ as auxiliary lemmas, not as interfaces.
   - Non-generator count: a non-generator α has [F₂(α):F₂] = k with k | s and k < s, so α^{2^k} = α. Bound the roots of X^{2^k} − X per k. This avoids enumerating the subfield lattice.

7. **M2: prove Lemma 4 generically, then specialize.**
   - State it over a finite separable extension K/F with nondegenerate trace form; mathlib supports this setting. Use `Matrix.det` on `Fin 3` together with the triple/cross-product identities for the radical and full-mode-image facts.
   - Represent the constructed field as `AdjoinRoot p` and take σ = `AdjoinRoot.liftHom p t`. It is bijective because it is an injective map between fields of equal cardinality.
   - Define the executable trace as the Frobenius sum and prove it equal to `Algebra.trace` before using nondegeneracy.
   - I have not confirmed the exact mathlib lemma names.

8. **M2.6: add the F4 bridge lemmas explicitly.** These are: symmetry of each B_j, so diagonal equations are redundant; symmetry and zero diagonal of D_T C in arguments 1–2, so i < j slices span W(D_T C); and the subtraction-to-addition specialization in characteristic 2.

9. **M4: budget for verified F₂ elimination as a major item.**
   - The checks `dim balance = s`, independence of powers, and "solution exists" all need completeness of elimination: rank plus nullity, and that the nullspace basis spans. Witness checking alone is not enough.
   - Mathlib's matrix rank is noncomputable. Expect to write and verify an echelon-form algorithm on `Fin m → Fin k → ZMod 2` (or `Bool`), with the invariants proved.
   - Prefer Boolean-array matrices to packed `Nat` words in the formal constructor. Proofs about packed bit manipulation are costly.

10. **M4: make the Rabin test bidirectional and place it on two different critical paths.**
    - Soundness (test passes ⇒ irreducible): if an irreducible factor g has degree k ≤ s/2, then `AdjoinRoot g` is a field with 2^k elements, so g divides X^{2^k} − X. This belongs on the verifier path.
    - Completeness (irreducible ⇒ test passes) belongs on the good-trial path.
    - Decide the p = X / s = 1 convention (F6).

11. **M6: prove tight bounds, then weaken.**
    - Prove O(n⁹) time and O(n⁶) space per trial, with explicit constants, for the bit-array constructor. Use a cost-instrumented monad whose erasure equals the M4 function, and track peak live storage explicitly.
    - Derive the envelopes by monotonicity, with the counter amortized.
    - This removes any need to reason about polylog factors.

12. **Split claim labels in advance.** Fix the exact wording allowed at each stage, for example:
    - after verifier soundness: "Lean-certified verifier soundness";
    - after M5: "Lean-certified correctness, probability and termination";
    - after M7: "complete".

    This prevents drift in labels if M6 stalls. The plan already says that finishing M2 or M5 leaves S006 incomplete. Make the permitted intermediate statements equally explicit.

13. **Coverage status vocabulary** (see F8): use `proved_generalization`, `bridged`, and `proved_exact`. Only `proved_exact` for every required obligation can set `complete: true`.

14. **Keep Python refinement separate, as the plan already does.** A verified Lean constructor certifies the §5 algorithm only. Nothing about `src/recovery.py` follows from it, including its O(n⁹) packed-integer stage.
