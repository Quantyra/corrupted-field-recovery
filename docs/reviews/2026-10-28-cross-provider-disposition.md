## Claude findings and disposition

- **F1, missing explicit resource model: accepted as a specification clarification.** The post-publication [resource-model clarification](../resource-model-clarification.md) names a bit-cost random-access model, charges indexing and primitive arithmetic, distinguishes streamed randomness from operational memory, and requires separate live-workspace and counter bounds. M0 must freeze this clarification with the formal target. No claim is made for arbitrary machine-model simulation or a naive single-tape implementation. The numerical published envelopes are unchanged; the clarification was not in the original archive.
- **F2, soft-O and space: partially accepted.** Make the formal asymptotic convention and additive workspace/counter accounting explicit. A permitted logarithmic factor in h is not a factor N, so the existing loose upper bound does not contradict the statement that storage has no factor N. Do not automatically strengthen the theorem to tilde-free time/space bounds. Amortized counters are a possible implementation improvement requiring their own proof, not a prerequisite for the existing bound.
- **F3, interpreter overhead: accepted for the certification target.** The mathematical constructor's resource proof rests on proved primitive costs and representation semantics; Python packing/runtime observations stay separate. The clarification and M0/M6 state this explicitly. Python refinement remains unclaimed.
- **F4, symmetry/slice bridges: accepted.** M2b names contraction symmetry and redundant diagonal balance equations, plus first-two-slot symmetry/zero diagonal of the displacement. These prove that the implemented i<j slices span the full third-mode image without falsely assuming three-slot alternation.
- **F5, fourth coordinate: accepted.** M3 explicitly takes the first coordinate relative to the sampled field basis `(v1,v2,v3)`. The existing proof's preceding fixed-basis condition supplies the intended interpretation; this does not alter the estimate.
- **F6, p=X: validated and corrected in the working Python companion.** The published `modulus < 3` guard rejected the irreducible degree-one polynomial X. It now rejects only values below 2 and applies the same squaring/gcd test. Focused regressions cover both degree-one presentations, clean/full-support certificates, altered tensors and reducible/constant polynomials. The full recovery suite passes unchanged trial counts. This was outside the sufficient success promise and did not invalidate accepted-certificate soundness. The immutable release keeps its original bytes; the correction is post-publication.
- **F7, literal totality wording: clarified.** The checker docstring now describes checking serialized values without trusting discovery state. The trace invariant and finite resource assumptions remain proof/refinement obligations; no demonstrated reachable arithmetic failure in valid field operations was found. Ordinary resource-exhaustion exceptions are not new mathematical counterexamples.
- **F8, abstract versus concrete coverage: accepted.** The existing proved `two_translate_image` is now explicitly `abstract_kernel_only`. A separate required `two_translate_bridge` is unformalized, and strict readiness requires it. The generic proof is retained; no theorem or build claim is replaced by metadata alone.
- **F9-F12: retained with scope.** Split scalar inclusion from the hard four-contraction inclusion; use slack rather than require stronger constants; preserve compatible output rather than planted uniqueness; retain fixture-assisted test disclosures. Additional ordinary-random nonzero-error coverage remains optional and is not a proof substitute.
- **Plan architecture: accepted with controls.** Add a frozen reviewed proposition/type audit, non-vacuity examples, early standalone verifier soundness, finite product/first-success amplification, explicit elimination completeness, and separate irreducibility soundness/completeness paths. Suggested mathlib API names and library-availability claims must be checked against the pinned sources before implementation.

## Agy findings and disposition

- **F1, operational proof burden: partially accepted.** Prefer a cost-instrumented finite-array algorithm with proved erasure and explicit current/peak storage. Validate the approach with a small arithmetic/elimination prototype before the whole constructor. An abstract field-operation counter or a Writer total alone does not prove bit complexity or working space. No unsupported claim about absence of suitable mathlib libraries is adopted.
- **F2, global invertibility: accepted and already anticipated.** The current abstract export has the stronger global-invertibility hypothesis. M2b must prove the manuscript's restricted-dual-injectivity bridge; merely specializing to nonzero scalar actions would establish the application but would not by itself close the more general manuscript lemma.
- **F3, proposed R<n condition for unconditional soundness: rejected as unnecessary.** The verifier requires c!=0 directly and checks the exact identity. For R=n, the error may cancel a nonzero compatible tensor and still be a valid representation, with no uniqueness claim. The proper-support argument is used only to prove that any solved coefficient system on a good trial has nonzero compatible component. A saved independent edge case uses n=3, K=F2, identity coordinates, c=1, E=det and C=0; all 512 vector triples satisfy det+det=0, and the checker accepts it while rejecting zero c, an insufficient rank cap and an altered tensor. This finite check illustrates the logical distinction; it is not a proof of the general theorem.
- **F4-F5 and plan refinements: accepted/reaffirmed.** Use finite counting/product tapes rather than infinite stopping-time machinery; split M2 into field-identification and transport/defect checkpoints; explicitly prove alternation implies symmetry, greedy quotient-basis progress, and the polynomial-test bridge. The plan already required these general obligations; the revised acceptance contracts make the critical steps more visible.
- **Reported 'blocking issues': scope safeguards, not demonstrated new failures.** Executable paths must avoid noncomputable choice, while ordinary classical proof foundations remain allowed and audited. Compatible representation is existential and does not mean unique planted recovery. Both remain explicit requirements. `Classical.indefiniteDescription` is not treated as a newly discovered independent axiom; executable computability and transitive axiom auditing are distinct checks.
