## Additional resource-accounting correction

**Medium, manuscript implementation accounting:** `manuscript/main.tex` Section 6 attributes O(n^6) bit operations to constructing exterior columns, while `src/recovery.py` `residual_columns` repeatedly evaluates `packed |= coefficient << pos` on immutable Python integers. There are O(n^3) columns and O(n^3) basis coefficients per column. A mutable preallocated bit array can indeed write each calculated bit in O(1), giving the stated O(n^6) abstract bound, but Python big-integer shifts and OR may allocate/copy O(n^3) bits per update. A conservative bound for this implementation is therefore O(n^9) bit operations, with O(n^6) bits for the full collection of packed columns, under the usual linear-cost big-integer operations model. Qualify the O(n^6) claim as applying to the mutable-bit-array algorithm and charge the Python routine O(n^9); this remains within the manuscript's deliberately loose soft-O(n^12) per-trial envelope. This is a supported accounting correction, not a demonstrated violation of the headline bound.
