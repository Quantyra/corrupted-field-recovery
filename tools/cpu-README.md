## Transport and recovery

`python tools/cpu_cfr.py screen --host cpu-02` performs a read-only resource screen; it is not admission. SSH uses the existing fixed `cpu-02` or `cpu-01` host alias with an explicit `-l quantyra-worker`, BatchMode, IdentitiesOnly and strict host-key checking. The role override never falls back to the alias's administrative login; the remote UID must still be 986. No new SSH alias is needed once the owner qualifies worker access.

After owner qualification, `python tools/cpu_cfr.py submit --run <run-id> --admission <local-owner-record> --admission-sha256 <owner-pin>` first validates local immutable files, then runs a metadata/control-only remote preflight against the independently pre-existing owner record. Proof bytes are uploaded only after preflight passes. The server rechecks under the host lease, creates the run directory atomically without overwrite, verifies every uploaded byte, then releases the staging lease. The runner independently rechecks and acquires the compiler lease; any intervening competing workload causes a closed failure, never preemption. Submit remains attached over SSH for the bounded run; the child owns a separate session and can remain observable if transport is lost.

The local exclusive `submission-attempt.json` is written before the launch-capable request. A repeated submit never restarts it, including after SSH/observation timeout. Use `observe --run <run-id>` to inspect actual owned PID/start-time/campaign/group handles and terminal state; `collect --run <run-id>` waits for stopped writers, verifies file/log/source/dependency/control/compiler/audit/type fingerprints and retains raw evidence under a new collection directory. Missing handles/terminal evidence stays explicit; collection is not semantic acceptance. Staging failures or missing custody markers require review rather than overwrite or automatic retry. The exact captured `cpu_cfr.py` remains runnable from its capsule for recovery after current tools change. No service, reboot schedule, cleanup or automatic source publication is installed.

The client exits successfully when an RPC completes, even if the returned compiler receipt failed. Inspect actual terminal stage/exit evidence; client exit 0 is not Lean acceptance. Large packets/collections above the 64 MiB bounded JSON transport cap require separate handling and are never silently truncated.
